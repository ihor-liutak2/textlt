Different Workflows. One Text Workspace.

Discover how TextLT supports everyday work with documents, notes, and reusable actions.

From research drafts to server configuration, related text often ends up spread across tools. TextLT is a native C++ terminal workspace that brings your files, notes, reusable text, and remote resources together around the project at hand.

Everything Related to Your Project, Together

Register an existing folder as a project, then select it from the sidebar. The project sets the document browsing context and can link its own Notes group, Actions group, and saved remote connection. Choose a different project when moving between activities.

In the examples below, Actions supply reusable clipboard text. Text Processors apply built-in or Lua transformations to document text.

A Practical Workspace for Software Developers

Keep source files, configuration, and technical notes in reach while you work in the terminal.

Backend Application Development

Documents
Source and configuration files, README, technical notes, and test specifications.
Notes group
Implementation ideas, architecture decisions, investigation results, and known defects.
Actions group
A Release page with a commit summary template and reusable test-command text.
Remote connection
An optional SFTP connection to a development server.

Example workflow

  1. Select the project and open the source or config file beside its README. Use syntax highlighting and Find and Replace while checking the relevant project note.
  2. Copy the summary template from Actions. To transform selected source text, run a separate Text Processor, such as Trim trailing spaces.
  3. Review the working diff in Tools → Git. Open Remote Files for the assigned server when the change also needs a remote review.

Use TextLT alongside your build, test, and debugging tools.

A Workspace for Research and Scientific Writing

Keep the draft, extracted material, and research notes organized around a local project.

Scientific Research Publication

Documents
Article drafts, study methods, experimental records, and a plain-text reference list.
Notes group
Hypotheses, literature notes, observations, and reviewer comments.
Actions group
A Manuscript page with an observation template and a reusable reviewer-response outline.
Remote connection
Optional SFTP access to text files on a research server.

Example workflow

  1. Open the draft and references side by side. Record the source and interpretation of an observation in the project’s Notes group.
  2. Paste the observation template from Actions. Use Normalize spaces or a configured Lua processor to clean selected text before moving it into the draft.
  3. Review changes in Git if the draft is in a repository. For proofreading, listen on a supported system with Piper set up, or use an optional rephrasing mode and review the result.

Support Teaching and Learning

Teachers can organize preparation by course. Students can use the same folder-and-notes pattern for each class or assignment.

Software Engineering Course

Documents
Lecture outlines, lab instructions, code examples, and project briefs.
Notes group
Learning objectives, questions, teaching observations, and study summaries.
Actions group
Reusable assignment headings, feedback text, and a lab checklist template.
Remote connection
Optional access to a configured lab server.

Example workflow

  1. Register a course folder and open a lab handout beside its code sample. Keep unanswered questions in the course’s Notes group.
  2. Copy an assignment outline from Actions, then use a Text Processor to clean up pasted text. Choose a theme and shortcuts that suit the terminal used in class.
  3. Use Git to inspect tracked changes. With optional tools configured, review a suggested translation of an instruction or listen to a handout.

Work Naturally Across Local and Remote Systems

Keep operational notes and configuration files close to the remote environment they describe.

Linux Server Administration

Documents
Service configuration, deployment notes, runbooks, and extracted log text.
Notes group
Maintenance procedures, investigation findings, and operational checklists.
Actions group
A Maintenance page with an incident summary template and command snippets to copy.
Remote connection
An assigned SFTP connection configured through an OpenSSH host alias.

Example workflow

  1. Select the server project and open its Remote Files view. Open a remote configuration file in Docs and review the relevant runbook note.
  2. Use Find and Replace for a specific text change. Copy command snippets from Actions for use in a separate terminal session.
  3. Save the local cached copy. In Remote Files, choose Sync Last when ready to upload the saved edit.

Notes group

Example workflow

Keep Everyday Information Organized

Use separate project folders and Notes groups for work, study, and personal interests.

Personal Workspace

Documents
Personal plans, lists, working drafts, and reference files.
Notes group
Ideas, reminders, learning notes, and short observations stored locally.
Actions group
A Weekly Review page with reflection prompts and a reusable packing checklist.

Example workflow

  1. Open a recurring plan from Recent Files or Favorites. Capture an idea in the project’s Notes group so it stays with the right activity in local Notes storage.
  2. Copy a checklist from Actions and paste it into a working document. Use Normalize spaces when bringing in text from another source.
  3. Choose a theme or shortcut bindings for the terminal, then use Distraction Mode while writing.

Work With Text Across Languages

Work on language variants in UTF-8 text and record the reasoning behind terminology choices.

Multilingual Documentation

Documents
Originals, translated drafts, language-specific versions, and a glossary.
Notes group
Vocabulary, translation observations, and terminology decisions.
Actions group
Reusable headings and formatting templates shared across language versions.

Example workflow

  1. Open the source and target documents. Select a passage in an editable copy and open Tools → Quick AI. With no selection, Docs uses the current paragraph.
  2. With a model active in AI Settings, choose a mode such as Fluency or Formal. To translate, enable Translate, choose a target language, and select the source language or Auto detect. Select Do.
  3. Review the result. Use Change to replace eligible source text, or Copy Result to paste into a separate draft. On a supported Piper setup, choose an installed voice for the language and use Tools → TTS to listen from the cursor before saving.

Quick AI is optional and uses a configured local Ollama server or external provider. Review wording and terminology before using a result.

Your Workspace, Wherever You Work

Use a consistent terminal workflow on Linux, in WSL, or in a compatible Linux environment on a server or virtual machine.

Distributed Editing Workspace

Documents
Local references, environment-specific configuration files, and handoff notes.
Notes group
Setup details and terminal-specific shortcut choices.
Actions group
Reusable handoff messages, environment checklists, and command text.
Remote connection
A configured remote connection for file access from the current TextLT instance.

Example workflow

  1. Run the Linux build in the Linux environment, including WSL. The native Windows x64 build is a separate release.
  2. Use Help → Keyboard Shortcuts to adapt bindings to the keys your terminal sends. Set a theme locally and use the sidebar to switch projects and documents.
  3. Browse the assigned remote connection from TextLT. When editing a remote file, save the cached copy and upload it explicitly with Sync Last.

The Roadmap describes proposed TextLT Connect device exchange and independent synchronization.

Less Switching. More Focus.

A shared workspace can reduce trips between tools. Keep related information under your control, reuse text and transformations, and open associated remote files as needed. Configure the keyboard and interface for the terminal you work in.
