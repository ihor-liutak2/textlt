The Road Ahead

Building an independent future for text and document workflows.

TextLT is an independent, native C++ terminal workspace for creating, editing, organizing, processing, and exchanging text. Its long-term direction is to connect documents, notes, actions, projects, and devices while keeping text portable and everyday editing straightforward.

The initiatives below are proposals. The three horizons describe priorities without setting release dates or delivery commitments.

One Environment. Connected Workflows.

Keep related files, notes, reusable text, and remote resources within one working context. The goal is to reduce application switching while keeping plain text accessible, information under the user’s control, and interfaces open to other tools.

Three Development Horizons

Initiatives can evolve independently within these priorities.

  1. Horizon 1

    Strengthen the Foundation

    Refine document workflows, project switching, Notes and Actions integration, terminal input, configuration, reliability, and usability.

  2. Horizon 2

    Connect the Workspace

    Explore TextLT Connect, remote workflows, independent synchronization, portable projects, and reusable Action collections.

  3. Horizon 3

    Extend Document Capabilities

    Investigate structured documents, information relationships, document profiles, validation, processing interfaces, and broader format interchange.

Strategic Initiatives

TextLT Connect

Connect devices. Exchange information. Keep control.

Moving a text selection between a laptop, server, or virtual machine can mean switching tools or creating a temporary file. TextLT Connect would let compatible instances exchange selections, whole documents, notes, and files over a configurable network. A recipient could open incoming text as a new document in the current workspace.

Explore trusted device discovery and registration, transfer confirmation, and integrity checks. A lightweight service using HTTP interfaces and JSON messages is one option. Authentication, authorization, secure transport, and network configuration would need evaluation before choosing an architecture.

The long-term goal is exchange without a mandatory central service. Documenting the protocol could also make integration with external applications possible.

Beyond Plain Text

Richer document capabilities without losing simplicity.

Explore optional organization for scientific writing, technical specifications, requirements, project records, education, and personal knowledge. The goal is to keep the original text independently readable while supporting structured navigation and reuse.

Investigate metadata alongside the text, sections with stable identifiers, paragraph metadata, information entities and relationships, internal references, templates, and profiles. Consistency and completeness checks could use that structure. Portable, backward-compatible storage is a design objective.

Your Information Across Your Devices

Independent synchronization. TextLT Connect would exchange individual items. Synchronization would keep selected information consistent across environments over time.

Notes currently stores revision metadata locally. Sync Last uploads a saved remote copy on request. Explore ongoing synchronization for notes, selected document collections, project information, Actions, and optionally themes, shortcuts, and other settings.

Let users choose destinations. Investigate change detection, conflict identification and resolution, recovery, and synchronization history before selecting a protocol.

Reusable Operations for Everyday Work

Today Actions cards store reusable text and can be imported. The separate Text Processors tool runs built-in transformations and parameterized Lua operations.

Explore portable Action collections, export and templates, and project-specific workflows. For processors, investigate sequential execution, clearer parameters and feedback, improved Lua tooling, and validation and testing.

Documented interfaces and portable definitions could help developers share and contribute reusable operations.

A Complete Workspace for Every Project

Today a project sets the local folder context, can associate dedicated Notes and Actions groups, and can reference a saved remote connection.

Explore faster switching, project-specific settings and document collections, and restoration of a project’s working state. Templates and import and export of portable project definitions could make workspaces easier to reuse across environments.

Documents Without Boundaries

Build on existing plain-text editing and document text import. Explore broader import and export, more reliable text extraction and encoding handling, and better preservation of headings, lists, and other structure during conversion.

Improve Markdown workflows and investigate established conversion tools, reusable transformation pipelines, validation of conversion results, and documented interchange interfaces.

Make Text Accessible

Build on configurable shortcuts, themes, and text-to-speech. Explore more predictable keyboard navigation across terminals and layouts, improved Unicode and multilingual input, and high-contrast appearance options.

Investigate simpler links between menus, dialogs, and shortcuts, easier navigation through long or structured documents, and better listening and proofreading workflows.

Software Built to Last

Build on the current component boundaries, platform builds, and automated tests. Improve document recovery, configuration handling, error reporting, and regression testing across platforms. The research evaluation framework outlines ways to assess those changes.

Investigate more reproducible builds and predictable installation and updates. Maintain technical documentation, review dependencies, evaluate resource use, and preserve access to older documents.

Opportunities for Collaboration

Developers, universities, research institutions, and technology organizations could explore these topics with TextLT, including European initiatives that work on independent and interoperable software.

  • Independent workspaces Local-first architecture, distributed document exchange, and user-controlled synchronization.
  • Structured information Open document formats, requirements traceability, consistency, and verification.
  • Accessible interfaces Terminal interaction across platforms and keyboard layouts, plus listening and proofreading workflows.
  • Sustainable software Reusable text-processing interfaces, maintainability, and long-term document access.

Development Principles

Local-first
Keep core workflows available without a required external service.
User ownership
Let users retain access to and control over their documents and information.
Open interoperability
Favor portable formats and documented interfaces that compatible tools can use.
Incremental evolution
Build new capabilities on stable components and proven workflows.
Terminal-native simplicity
Keep everyday interactions straightforward as advanced tools grow.
Extensibility
Add capabilities through clearly defined components and interfaces.
Resource awareness
Evaluate practical use across different hardware and working environments.
Long-term maintainability
Prioritize testing, documentation, and compatibility as the software evolves.
