Research. Engineering. Innovation.

Exploring independent technologies for the future of text and document workflows.

TextLT is a native C++ terminal application and a practical foundation for experimental work on documents, information organization, and distributed text environments. The directions below are proposed investigations grounded in user ownership, interoperability, accessibility, software independence, and long-term maintainability.

A Practical Foundation for Innovation

TextLT’s document sessions, local Notes storage, clipboard Actions, and project context provide a working application in which to study changes. Configurable terminal controls, text processors, and automated tests offer practical starting points for prototypes and evaluation.

Research Directions

Rethinking the Textual Document

Plain text is portable. Scientific articles, teaching material, and technical specifications may also need structure they can preserve across edits and applications.

Existing foundation
TextLT separates document sessions and text buffers from pane state. Existing import tools extract text from several document formats.
Research questions
Can document elements keep stable identities during edits? How should references and metadata stay consistent as paragraphs split, move, or disappear?
Proposed experiments
Prototype optional metadata alongside plain text, paragraph identifiers, entity relationships, and document profiles or templates. Explore requirements traceability and consistency and completeness checks.
Potential outputs
Experimental models and specifications, validation algorithms, a prototype, evaluation datasets, and technical documentation.

Text Beyond a Single Device

Text and notes often move among laptops, servers, and virtual machines. Each transfer or synchronization mechanism introduces choices about trust, integrity, and conflict handling.

Existing foundation
TextLT can open a cached copy through a configured remote connection and explicitly upload a saved edit. Notes store local revision and device metadata. TextLT Connect and ongoing cross-device synchronization are roadmap proposals.
Research questions
How can devices establish trust, verify content across a transfer, and identify or resolve conflicting changes without mandatory central infrastructure?
Proposed experiments
Explore direct exchange and local discovery, trusted device registration, transfer verification, and independent synchronization. Compare ways to document interfaces so independent implementations can interoperate.
Potential outputs
Prototype networking components, protocol specifications, reference implementations, interoperability tests, and reliability evaluations.

Reusable and Verifiable Text Operations

Repeated cleanup, conversion, and extraction steps become easier to compare and share when their inputs, parameters, and results are explicit.

Existing foundation
Actions cards hold reusable clipboard text. The separate Text Processors tool uses registry definitions to run built-in operations and parameterized Lua scripts.
Research questions
Can an operation be described independently of its implementation? How can pipelines validate parameters, handle errors, and reproduce results across projects?
Proposed experiments
Prototype portable operation descriptions, composed transformations, and validation with reference inputs and expected outputs. Explore reusable Action collections and predictable processor execution.
Potential outputs
Processing specifications, a prototype framework, reusable definitions, tests, and reference examples.

Connecting Documents, Notes, and Operations

A project’s drafts, decisions, reusable text, and remote files often need to be found together when work resumes.

Existing foundation
A project sets the folder context and can link dedicated Notes and Actions groups and a remote connection. Open document sessions belong to the shared workspace.
Research questions
Which information belongs in a portable project description? What workspace state helps a user resume work and reduces navigation effort?
Proposed experiments
Prototype project metadata, reusable templates, relationships between resources, and project-specific restoration. Compare tasks that combine local files, notes, reusable text, and remote resources.
Potential outputs
Information models, project configuration specifications, workspace prototypes, and workflow evaluation methods.

Making Terminal Software More Accessible

Terminals vary in how they report key combinations. Discoverable navigation and configurable controls can help users work across environments.

Existing foundation
TextLT has configurable shortcuts, menus and dialogs, themes, UTF-8 editing, and optional speech playback on supported setups.
Research questions
Which commands are difficult to discover? How do keyboard layouts, contrast, and terminal behavior affect navigation and text entry?
Proposed experiments
Compare menu and shortcut designs, multilingual input, high-contrast palettes, speech workflows, and navigation in controlled studies. Record task completion, errors, keyboard compatibility, and participant feedback.
Potential outputs
Prototype interactions, a terminal compatibility test matrix, reproducible task scripts, and usability findings if studies are conducted.

Keeping Digital Information Under User Control

Long-term access to documents depends on portable representations and the ability to choose where information is stored and exchanged.

Existing foundation
Core editing and processing run locally. Users can work with plain-text files and configure external resources when needed.
Research questions
Which dependencies are necessary for core workflows? Can documents and connection interfaces stay usable across independent implementations and operating environments?
Proposed experiments
Investigate import and export, documented interchange, user-controlled storage and synchronization, and dependency analysis. These questions are relevant to European research on digital independence, open standards, accessible tools, and sustainable infrastructure.
Potential outputs
Portability test cases, interchange specifications, and an assessment of dependencies and long-term document access.

Engineering Software for Long-Term Use

Sustainable software depends on maintenance effort, compatibility, and resource use across hardware and platforms.

Existing foundation
The native C++ application has separate document, persistence, and integration components. CMake and CTest support builds and automated regression tests on Linux, Windows, and macOS in release CI.
Research questions
How does added functionality affect coupling, compatibility, and maintenance? What resource costs emerge under comparable workloads?
Proposed experiments
Measure startup, memory and CPU use, and energy where instrumentation permits. Study dependency changes, reproducible builds, regression behavior, and compatibility with older document and configuration data.
Potential outputs
Measurement methods, reproducible experiments, technical reports, and engineering recommendations.

From Research Questions to Practical Results

Technology Initiatives

Proposed research and development projects. Deliverables are possibilities for future work.

TextLT Connect

Moving text among working environments can require intermediate tools.

Research challenge
Establish device trust and verify that a received item matches the selected source.
Proposed technology
Prototype direct device exchange with documented interfaces.
Potential applications
Developer handoffs, research notes, and exchanges between local and remote environments.
Potential deliverables
A prototype, protocol draft, and transfer and interoperability tests.
Related roadmap direction for TextLT Connect

Open Structured Text

Complex documents often need links and metadata that can survive revisions.

Research challenge
Keep structure aligned with edits while preserving the underlying text.
Proposed technology
Prototype an optional metadata layer with stable identifiers, references, and checks.
Potential applications
Specifications, publications, research records, and teaching material.
Potential deliverables
A document model, example corpus, and validation prototype.
Related roadmap direction for Open Structured Text

TextLT Action Framework

Repetitive text transformations are easier to reuse when their parameters and effects are documented.

Research challenge
Describe operations portably and verify composed results.
Proposed technology
Prototype structured processor definitions and a workflow test harness. Keep these distinct from clipboard Actions collections.
Potential applications
Text normalization, publishing preparation, and recurring project cleanup.
Potential deliverables
Operation specifications, example workflows, and regression tests.
Related roadmap direction for TextLT Action Framework

Accessible Terminal Workspace

Terminal input and visual presentation vary among environments.

Research challenge
Make commands easier to find and test navigation across keyboard layouts and emulators.
Proposed technology
Prototype interaction, shortcut, contrast, and listening improvements.
Potential applications
Terminal editing in teaching, research, and day-to-day work.
Potential deliverables
Interface prototypes, keyboard test cases, and a usability evaluation plan.

Measurable Engineering Outcomes

Choose evaluation criteria and comparison methods before an experiment. Record workloads, platforms, versions, and uncertainty so another team can reproduce the evaluation.

Document engineering
Structural consistency, metadata preservation, format compatibility, and validation correctness.
Distributed environments
Transfer reliability and latency, content integrity, and consistency after changes or conflicts.
Text processing
Transformation correctness, repeatability, error detection, and runtime for specified workloads.
Human–computer interaction
Task completion time, interaction errors, key compatibility, and participant feedback.
Software sustainability
Memory, CPU use, dependency complexity, maintainability indicators, and regression reliability.

Independent Technology Development

Keep users in control of their information. Define component responsibilities, document interfaces, and favor engineering results that others can evaluate and reuse. Respect the project license and the terms of third-party dependencies when sharing software or results.
